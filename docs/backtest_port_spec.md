# 3+1 SOP v5 → backtest-lab 移植規格

給本機 Claude Code（`C:\backtest-lab`）用。目標：把 `3plus1_sop_v5.pine` 的 **3+1 SOP 進場**
移植成 backtest-lab 的 Python 策略，先與 TradingView 交易清單逐筆對帳，對上之後再跑長期資料。

backtest-lab 的必守規則（CLAUDE.md 第 3 節）全部照舊：UTC、不偷看未來、參數放 `configs/*.toml`、
對帳不一致只回報不改規則、每階段跑全部測試、使用者確認後才 commit、安裝套件或下載前先問。

## 2. 策略設定（Pine `strategy()` 宣告）

- `initial_capital=10000`，每筆固定 **1000 USDT 名目**（`strategy.cash`），不複利
  - 數量 = 1000 / 進場價，無條件捨去到小數 6 位（例：1000/63806.9 → 0.015672）
- 手續費：單邊 **0.05%**（每筆來回約 1 USDT）；滑價 0
- `process_orders_on_close=true`：**訊號那根 K 棒的收盤價進場**，不是下一根開盤
- `pyramiding=0`：一次一個部位
- `calc_on_every_tick=true` 只影響即時行情，歷史回測等同每根收盤計算一次

## 3. 匯出 CSV 時的指標設定

從 CSV 能確定的：
- 時間停損 = 100 根（預設值）
- 持倉中新訊號不是「反手」模式（沒有以進場訊號出場的交易）。「隱藏」與「灰色」對交易沒有差別

無法從 CSV 確定、**先假設為 Pine 預設值，對不上再問使用者**：
- `rr=1.0`、`confirmFrom=2`、`needOb2=false`、`fvgZone=true`、`engulfExtra=false`
- `swingLen=50`、`mitSrc="High/Low"`
- `biasFilter=false`（3+1 的偏見過濾，預設關）
- `useSpike=true` 但整份清單沒有突刺交易 → 可能是過濾後沒有訊號、被 SOP 持倉擋掉，或使用者關掉了

## 4. 規則導讀（Pine 行號為約略位置）

每根 K 棒收盤依序執行，**順序會影響結果，請照 Pine 的順序**：

1. **FVG 失效**（L246）：收盤穿越 FVG 遠端邊界就移除。
2. **擺動點**（L264）：兩套，內部 `sz=5`、Swing `sz=swingLen`。
   - `high[sz] > ta.highest(sz)` → leg=0（確認一個擺動高點在 `bar_index-sz`）；`low[sz] < ta.lowest(sz)` → leg=1。
     `ta.highest(sz)` 是包含目前這根的最近 sz 根，資料不足時為 na（比較結果為 false）。
   - leg 改變時才更新擺動點價位與位置，並把「已突破」旗標歸零。
   - `pHPrev / pLPrev` 是「更新前」的擺動點價位（等同 Pine 的 `level[1]`）。
   - `parsedHighs / parsedLows`：若該根幅度 ≥ 2×ATR(200)，高低點對調後存入。
3. **結構突破與 OB**（L315）：先內部（s=0）後 Swing（s=1），每套先向上後向下。
   - 向上突破：`close > 擺動高點 且 close[1] <= pHPrev`，且該擺動點尚未被突破過。
   - 內部結構的擺動點若與 Swing 擺動點價位相同，內部不算（留給 Swing）。
   - 突破前趨勢為反向 → CH（一律有效）；否則 → BOS，且曾有過 CH 時必須
     `close >` 「CH 那根起到前一根為止的最高點」（`sinceHArr`，在腳本最後 L863 才更新，所以不含目前這根）。
     無效的 BOS 仍會更新趨勢與突破旗標，只是不送出事件。
   - 趨勢初始值 0，所以第一次突破是 BOS。
   - **只有內部結構（s=0）會建立 OB**：取「被突破的擺動點那根」到「突破前一根」之間
     parsedLow 最低（多方）／parsedHigh 最高（空方）的 K 棒，區域 = 該根的 parsedHigh～parsedLow。
     無效的 BOS 也會建立 OB。最多保留 100 個，超過刪最舊的。
   - 掃蕩型（`obSw`）、位移（`obDisp`）只給突刺用，第一階段可先算好但不用。
4. **事件佇列順序**：結構事件（CH／BOS）→ 新 OB → 新 FVG。
5. **OB 失效**（L491）：多方 OB `low < obLo`、空方 OB `high > obHi` 就移除。**建立的那一根也會檢查**。
6. **新 FVG**（L514）：`low > high[2]` 且缺口 > 0.1×ATR(14)（空方相反；同一根多方優先）。
   ATR 用 Pine 的 `ta.atr`（RMA，也就是 Wilder 平滑），不是簡單平均。
7. **連招狀態機**（L553）：逐一處理事件。
   - 同向：記下種類；若這組已用過（`cUsed`）且事件是 CH 或 BOS，重新開放。
   - 反向 FVG 且已有方向：忽略。
   - 其他反向事件（或尚無方向）：方向改為該事件方向，四個旗標重設成只有這一種。
   - `armed = 有方向 且 種類數 ≥ 3 且 未用過`。
8. **回踩與確認**（L589）：只在 `armed` 時執行。
   - 已有「第 1 根」時：超過 3 根（`bar_index - cFirst > 2`）或收盤穿越區域遠端 → 取消，**同一根可以重新找**。
   - 找區域 `f_best`：同向、且（多方）區域下緣 < 收盤價，取上緣最高的一個（空方鏡像）。
     沒有任何符合的 OB 時改找 FVG。
   - 這根影線碰到區域近端（多：`low <= 區域上緣`）→ 這根是第 1 根，記下區域與 `firstMid=(open+close)/2`。
   - 確認（預設從第 2 根起，`bar_index - cFirst >= 1`）：多方 `close > 區域上緣 且 close > firstMid`。
   - 停損：同種類、比第 1 個區域更遠的最近一個區域的遠端；沒有就用第 1 個區域的遠端。
     不加任何緩衝。`risk = (close - sl) × 方向` 必須 > 0。
   - 停利 = `close + 方向 × risk × rr`。
   - **訊號成立就把 `cUsed` 設為 true，不論當時有沒有部位**（持倉中被隱藏的訊號也會消耗這組連招）。
9. **進場**（L644）：`goSig` 且空手 → 收盤價進場，掛停損與停利。
10. **出場**：
    - 停損／停利：進場的**下一根**起用影線判斷，成交價就是停損／停利價。
      跳空越過時 TradingView 以開盤價成交。
    - 同一根同時碰到兩邊：TradingView 的假設是「開盤較接近高點 → 開高低收，否則開低高收」。
      本專案規則是先算停損（有 1 分鐘資料先用 1 分鐘）。**兩者結果不同的交易請列出來回報，不要改規則。**
    - 時間停損（L838）：收盤時 `bar_index - 進場那根 >= 100` → 以該根收盤價平倉。
      這一根因為計算時還有部位，不會同時進新單。
    - 停損／停利在第 N 根盤中出場後，第 N 根收盤若有新訊號可以立刻進場（清單裡有 4 次）。

第一階段**不做**：突刺進場、TP1 後保本、偏見燈號、盤中預覽、反手模式、所有畫圖。

### 偏見（之後要做時參考）
`request.security(..., f_bias(), lookahead_on)` 搭配 `[1]`、`[2]`，等同「該高週期最近兩根**已收盤**的 K 棒」。
Python 版必須只用已收盤的高週期 K 棒，並附防偷看未來的測試。

## 5. 資料

- 對帳必須用 **BingX BTCUSDT.P 的 5 分 K**。幣安的價格和 BingX 差幾塊錢，
  收盤突破的判斷會不同，用幣安資料無法逐筆對上。
- 取得方式（擇一，先問使用者）：
  1. BingX 公開 K 線 API（不需要金鑰）下載 2026-08-01～2026-11-12；
  2. 請使用者從 TradingView 匯出圖表資料。
- **暖機問題**：結構狀態會受起點影響。TradingView 的 5 分圖歷史長度有限，
  第一筆交易在 08-13，圖表第一根 K 棒大約在那之前幾天。請向使用者確認圖表最左邊那根的時間，
  從同一根開始算。前幾筆對不上、之後收斂是可以接受的，但要寫在報告裡。
- 長期回測用 backtest-lab 現有的 BTC 5m（2018 起）。

## 6. 實作階段（每階段結束都跑全部測試並回報，等使用者確認）

1. **結構模組**：擺動點、CH／BOS、OB、FVG，寫成獨立模組，單元測試用手算的小例子。
2. **SOP 策略**：連招狀態機＋回踩確認＋出場，註冊到 `STRATEGIES`；
   同步 `ui_data.py`（`strategy_kind`、`engine_path_for`、`PARAM_INFO`、`CHOICES`）。
   收盤價進場若共用引擎不支援，就在策略類別裡寫自己的 `run()`。
   參數全部放 `configs/sop_3plus1.toml`，數值就是第 2、3 節的預設值。
3. **對帳**：比對進場時間、方向、進場價、出場時間、出場價、出場原因。
   回報「幾筆對上／共幾筆」，並逐筆列出不一致的原因分類
   （暖機、資料差異、同根雙觸、規則理解不同）。對帳測試要設 `time.end`。
4. **長期回測**（對帳通過、使用者同意後才做）：
   - 參數完全不動，直接跑 2018 起的 BTC 5m，分年列出筆數、勝率、PF、淨損益、最大回撤。
   - 手續費分別用單邊 0.05%（與 TradingView 相同）和專案慣用的 0.1% 各跑一次。
   - 2026-08-13～11-12 這段是設計策略時看過的，標「樣本內」；之前的年份是樣本外。
   - **看過長期結果之後再調的任何參數，一律標樣本內。**
5. **之後的題目**（另外討論，不要自行開始）：最小停損距離、偏見過濾、突刺進場、固定風險下單。

## 7. 已知風險

- LuxAlgo 結構的細節多，第一次對帳很可能不到 100%。先找最早出現分歧的那一筆，
  往回看是哪個事件（擺動點、突破、OB 建立或失效）不同，一次修一個。
- 若怎麼對都差很多，請使用者在 TradingView 打開「顯示 CH / BOS 小三角形」，
  截圖某一段給你比對事件，比猜測有效率。
